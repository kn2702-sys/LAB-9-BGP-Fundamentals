# BUILD — Lab 9 by hand in Cisco Packet Tracer

Follow these steps to build the topology yourself instead of opening the
supplied `.pkt`. Everything here matches `configs/` and the generated file
exactly — same device names, same addresses, same configs.

**You need:** Cisco Packet Tracer 8.2 or newer.

## Step 1 — Place the devices

From the device palette, place left to right:

| # | Device | Model | Name it |
|---|--------|-------|---------|
| 1 | PC | PC-PT | PC-A |
| 2 | Switch | 2960-24TT | SW-A |
| 3 | Router | ISR 2911 | R1 |
| 4 | Router | ISR 2911 | R2 |
| 5 | Router | ISR 2911 | R3 |
| 6 | Router | ISR 2911 | R4 |
| 7 | Switch | 2960-24TT | SW-B |
| 8 | PC | PC-PT | PC-B |

Rename each device on placement (click the device, Config tab) so the CLI
prompts match the configs and this documentation.

Leave a visible gap between R2 and R3 — that gap is the boundary between
AS 65001 and AS 65002.

## Step 2 — Cable in this order

| From | Port | To | Port | Cable |
|------|------|----|------|-------|
| PC-A | FastEthernet0 | SW-A | FastEthernet0/1 | Copper Straight-Through |
| SW-A | FastEthernet0/24 | R1 | GigabitEthernet0/0 | Copper Straight-Through |
| R1 | GigabitEthernet0/1 | R2 | GigabitEthernet0/0 | Copper Cross-Over |
| R2 | GigabitEthernet0/1 | R3 | GigabitEthernet0/0 | Copper Cross-Over |
| R3 | GigabitEthernet0/1 | R4 | GigabitEthernet0/0 | Copper Cross-Over |
| R4 | GigabitEthernet0/1 | SW-B | FastEthernet0/24 | Copper Straight-Through |
| SW-B | FastEthernet0/1 | PC-B | FastEthernet0 | Copper Straight-Through |

## Step 3 — Configure the PCs

Double-click each PC → Desktop → IP Configuration → **Static**:

| PC | IP address | Subnet mask | Default gateway |
|----|-----------|-------------|-----------------|
| PC-A | 192.168.11.10 | 255.255.255.0 | 192.168.11.1 |
| PC-B | 192.168.12.10 | 255.255.255.0 | 192.168.12.1 |

## Step 4 — Paste the router configs

Open each router's CLI and paste the matching file from `configs/`
**in this order: R1, R2, R3, R4.**

| Router | Config file |
|--------|-------------|
| R1 | `configs/R1-Enterprise-Internal.txt` |
| R2 | `configs/R2-Enterprise-Border.txt` |
| R3 | `configs/R3-Peer-Border.txt` |
| R4 | `configs/R4-Peer-Internal.txt` |

Each file is a complete paste session: it starts with `enable` /
`configure terminal` and ends with `end` / `write memory`, so paste the
whole file in one go. If a line is rejected, don't improvise — check
[docs/TROUBLESHOOTING.md](TROUBLESHOOTING.md) first.

## Step 5 — First sanity checks (before BGP verification)

1. On R1: `ping 10.1.12.2` — the internal link to R2 answers.
2. On R4: `ping 10.2.34.1` — the internal link to R3 answers.
3. On R2: `ping 172.16.100.2` — the eBGP transit link answers at Layer 3
   (this only proves IP reachability, not that BGP is up — that's next).

## Step 6 — Verify

Work through [docs/VERIFICATION.md](VERIFICATION.md) top to bottom. It
lists every verification command, what the output should show, and the
misconfiguration drill.

## Regenerating the .pkt instead

The supplied `Lab-9-BGP-Fundamentals.pkt` was generated by
`scripts/build_topology.py` (pktlib) from the same `configs/` files:

```
pip install pktlib
python3 scripts/build_topology.py
```

The script prints the device/link counts it wrote and re-opens the file
to confirm it parses — 8 devices, 7 links.
